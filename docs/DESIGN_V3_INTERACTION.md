| 位置 | 现状 | 性质 |
|---|---|---|
| Tab 1 课表 | 周网格 + 周导航头 + 课程详情/操作 | 内容 |
| Tab 2 管理 | 当前课表信息 + 4 种导入 + 建表/编辑表 | 管理 |
| Tab 3 我的 | 6 个入口（主题/设置/全部课表/管理/导出/关于） | 管理 |

### 1.2 导入积木（5 条路径，8 种格式）

| 路径 | 格式 |
|---|---|

### 1.3 其他能力积木

节假日（nianbao API + 灰显/划线）、冲突布局 3 样式（叠层/折角/竖轨）、智能节次、撤销、课程配色（自动哈希/自定义/无色）、多课表、缩放、更新检查、四语言、高刷新率、深链编辑指定课程。

### 1.4 ⚠️ 实测发现的死代码与已禁用能力

**这一节是重设计的决策前提 —— 现状比交接文档描述的更空。**

| 项 | 实测证据 | 结论 |
|---|---|---|
| **5 种小组件（10 个配置）** | Manifest 中 10 个 receiver 全部 `android:enabled="false"`，且**全仓无任何** `setComponentEnabledSetting` 调用 | **产品层面完全不可用**，用户在小组件列表里看不到 |
| **上课前提醒 / 每日提醒** | 4 个 notification receiver 全部 `enabled="false"`，同样无动态启用 | **完全不可用** |
| `FluidCloudService` / `ScrollStripService` | Manifest 中 `enabled="false"`，仅被死掉的小组件子系统引用 | 死代码 |
| `TodayScreen.kt`（381 行） | `MainActivity` 只 import 未使用；`tab_today` 字符串零引用 | **死代码** |
| `WidgetManagementScreen` / `WidgetEditScreen` | 全仓无调用点，不可达 | 死代码 |
| 字符串 `import_qr` / `schedule_share_table` | 零引用 | 死资源 |
| `PinyinMatcher` | 仅 2 处引用 | 近乎游离 |

> **诚实交代**：上一轮我把"小组件层 Apple 化"当成已完成项汇报，
> 但实测证明这批小组件**在产品里根本不可用**。那次改造在代码层面有效、
> 在产品层面无效 —— 这个判断失误记在这里，避免后续再按"小组件已做完"来规划。

## 2. 重设计判据

用户给的核心隐喻：**功能是积木，交互是把积木填进去。** 所以本设计不新增业务能力为主，而是**重新组织既有能力的位置与操作方式**。

三条判据（按优先级）：

1. **时间尺度优先于功能分区。** 用户的心智是"我接下来上什么课 / 这周什么安排 / 这学期怎么调"，
   而不是"导入功能在哪个 Tab"。导航轴必须对齐时间尺度。
2. **频次决定可达性。** 每天看几十次的东西必须零点击直达；每学期用一次的东西允许深一层。
3. **不隐藏、不重复。** 遵守 HIG：tab bar 只做导航不做动作、不得隐藏；
   同一能力不得同时出现在两个入口。

## 3. 新信息架构：从「功能分区」改为「时间尺度」

### 3.1 旧轴的问题

```
旧：课表 ─┬─ 管理 ─┬─ 我的
         └ 内容   └ 管理+管理   ← 三个 Tab 里两个是管理，语义重叠
```

"导入新课表"这个**单一意图的任务**，被拆散在「管理」和「我的」两个 Tab 里：
课表页想加课要点 Dock 的 ＋ → 进 sheet → 选教务直连 → 跳 Activity。

### 3.2 新轴

```
新：今天 ──── 课表 ──── 设置
    (小时级)  (周/学期级)  (元级)
      内容      内容       管理
```

三个 Tab 是**同一件事的不同时间尺度**，切换成本最低。
管理类全部收进「设置」，不再与内容争夺导航位。

```
┌─────────────────────────────────────────────┐
│                                             │
│              内容区（随 Tab 变化）             │
│                                             │
├─────────────────────────────────────────────┤
│   今天        课表        设置                │  ← Liquid Glass，常驻不隐藏
└─────────────────────────────────────────────┘
```

### 3.3 各 Tab 定义

**Tab 1 · 今天**（新增可达入口 —— `TodayScreen` 重写后复活）

- **下一节课卡**：课程名 / 时间 / 教室 / 倒计时（新增）
- **今日时间轴**：纵向列表，按时间排列，当前进行中的课高亮
- **今日无课**：空态 + "本周还有 3 天有课"的上下文提示
- **首次进入无课表**：全屏引导 → 主 CTA「从教务系统导入」（特色功能前置）
- 为什么是首页：课表 App 最高频需求是"我下一节在哪"，不是"看整周网格"

**Tab 2 · 课表**

- **大标题**：`第 3 周`，副标题 `9月14日 – 9月20日`；滚动收起为 inline
- **导航栏右侧**：`＋` 添加课程（内容层动作，HIG 允许）、`⋯` 更多（导入/导出/周次范围）
- **三视图切换**（分段控件）：`周` / `学期` / `课程`（列表）
  - 周：现有网格
  - 学期：全部周的纵向总览（新增，用于看整学期分布）
  - 课程：按课程名聚合的列表 + **搜索**（接入已有 `PinyinMatcher`）
- **周次切换**：横向滑动换周 + 点击标题 → **全屏周次选择器**（替换现在的 DropdownMenu），
  选择器内含**学期进度条**与"回到本周"（新增）

**Tab 3 · 设置**（合并原「管理」+「我的」）

分组：

| 组 | 项 |
|---|---|
| **课表** | 当前课表 / 全部课表与学期 / 导入课表 / 导出课表 / 手动添加课程 |
| **显示** | 主题模式与强调色 / 显示设置（密度、可见星期、字段）/ 节假日 / 冲突样式 |
| **通知** | 上课前提醒（见 §5 决策） |
| **关于** | 检查更新 / 隐私 / 开源许可 / 反馈 |

### 3.4 移除的结构

| 移除项 | 理由 |
|---|---|
| **浮动 Dock** | HIG: *"Use a tab bar to support navigation, not to provide actions."* 且与 tab bar 功能重复 |
| **下滑收起 Dock** | HIG: *"Don't disable or hide tab bar buttons."* |
| 覆盖页栈（8 个 enum） | 改为标准 push/pop 导航，语义更清晰、返回键行为可预期 |

## 5. 关键交互设计

### 5.1 添加/导入课表：从「平铺列表」到「向导」

**旧**：底部 sheet 平铺 5 行（教务直连 / WakeUp / 文本 / 文件 / 手动），用户需自己理解差异。

**新**：全屏分步。

```
Step 1  选择来源
        ┌──────────────────────────┐
        │ 从教务系统导入      ★特色  │  ← 首选项，带说明
        │ 吉林建筑大学 · 需登录      │
        ├──────────────────────────┤
        │ 从文件导入                │
        │ ICS / CSV / JSON / HTML   │
        ├──────────────────────────┤
        │ 粘贴文本导入              │
        ├──────────────────────────┤
        │ 手动添加课程              │
        └──────────────────────────┘

Step 2  来源专属流程（教务：学校 → 登录 → 抓取）
Step 3  预览 + 冲突处理（复用现有 ImportPreviewDialog 能力）
Step 4  完成 → 跳转课表页并定位到新学期
```

**上下文触发**（不做常驻入口）：无课表时的首页空态直接给「从教务系统导入」大按钮；
学期切换时节气提示「新学期，去更新课表」。低频功能不该常驻抢注意力。

### 5.2 课程块操作

- **点击** → 课程详情 sheet（现有）
- **sheet 内** → 编辑 / 删除（现状把编辑放在长按菜单，多一步）
- **长按** → 快捷操作（改为 sheet 内操作后，长按仅保留触觉反馈确认）
- **冲突课程** → 除描边外必须有 `!` 符号（WCAG：颜色不得是唯一信息载体）

### 5.3 周次导航

- 横向滑动换周（保留）
- 点击标题 → 全屏选择器：周次网格 + 学期进度条 + 「回到本周」
- 大标题滚动收起（HIG 标准）

### 5.4 动效与反馈

沿用 v2 §6。新增：向导步骤间用**水平滑动转场**（符合"前进/后退"的空间隐喻），
不用淡入淡出（无方向感）。

## 6. 教务导入专项：实现、可用性与兼容性

> 这是用户明确要求保留且必须可用的特色功能。本节单独展开。

### 6.1 现有实现链路（实测）

```
JwImportActivity（流程控制器，3 个 Stage）
  │
  ├─ Stage.SelectSchool
  │    └─ SchoolSelectScreen
  │         └─ 数据源：JwImportViewModel.defaultWedoSchools()
  │              目前 1 所：吉林建筑大学
  │              url  = https://jwxt.jlju.edu.cn/sso/hnyyxyiotlogin
  │              type = JwProtocol.TYPE_ZF_NEW
  │              enableFetch = true
  │
  ├─ Stage.WebViewLogin
  │    └─ JwWebViewLoginScreen
  │         ├─ 域名白名单：lxr.jlju.edu.cn（认证）
  │         │              cas.jlju.edu.cn（认证）
  │         │              jwxt.jlju.edu.cn（装 JS 桥）
  │         ├─ onReceivedSslError → handler.cancel()  ← 安全红线，不可改
  │         └─ 页内注入 JwZfNewFetchJs
  │              → POST /kbcx/xskbcx_cxXsgrkb.html
  │              → window.__wedoBridge.onFetchResult({ok, data})
  │
  ├─ 解析
  │    └─ JwImportViewModel.parseHtml(html, type)
  │         └─ JwParserRegistry.parserFor(type)
  │              └─ FACTORIES: {"zf_new" → JwNewZfParser}   ← 唯一扩展点
  │                   └─ JwNewZfParser
  │                        支持两种页面结构：
  │                          · #kbgrid_table_0 + td[id] + .timetable_con（网格）
  │                          · #kblist_table + tbody 序号（列表）
  │                        失败 → JwParseDiagnostics 分类（7 类）
  │
  └─ Stage.ConfigureConfirm
       └─ AlertDialog：起始日期 + 课表名 + 节次时间表
            └─ JwImportViewModel.importAsNewTable(...)
                 └─ 单事务：建表 + 落库，失败回滚（不留空表）
```

### 6.2 可用性保障（现状已具备 / 需补强）

| 保障 | 现状 | 重设计后 |
|---|---|---|
| **失败可降级** | `IMAGE_OR_EMPTY_CELLS` 等提示"改用文件导入或手动添加" | 错误页直接给**两个可点按钮**（改用文件导入 / 手动添加），而非纯文字建议 |
| **导入不覆盖** | `importAsNewTable` 恒建新表 | 保留 |
| **事务安全** | 建表+落库单事务，失败回滚 | 保留 |
| **导入前可校正** | ConfigureConfirm 可改起始日期/表名/节次 | 改为向导 Step 3，信息分组更清晰 |
| **错误可理解** | 7 类诊断 → 用户文案（`DiagMapper`） | 保留分类，文案改为"原因 + 下一步动作"结构 |
| **不泄露响应** | 解析异常只记 code（`E_PARSE_FORMAT`），不回显响应片段 | **保留此约束** |

### 6.3 兼容性设计

**（1）多学校扩展 —— 当前存在一处硬耦合，必须解**

- 学校清单是**数据驱动**的（`defaultWedoSchools()`），加学校只需加一条 → ✅
- 但**域名白名单硬编码在 `JwWebViewLoginScreen`**（`lxr.jlju.edu.cn` 等三行常量）→ ❌ 耦合
- 后果：加第二所学校必须同时改 UI 层常量，容易漏改导致白名单不含新学校域名 → 登不进去或误放行

**重设计动作**：把白名单下沉到 `JwSchoolInfo.authHosts`，由 UI 层读取。
新增学校变成**纯数据改动**（一处），并可用契约测试锁住"每所学校都必须声明 authHosts"。

安全约束不变：白名单**严禁**扩为通配；SSL 错误必须 `cancel()`。

**（2）正方版本差异**

- 已同时支持 `#kbgrid_table_0`（网格）与 `#kblist_table`（列表）两种结构 → ✅
- 新增：`JwParserRegistry.FACTORIES` 按 `type` 分发，未来出现**新版正方**（如 `zf_new_v2`）
  或**老版正方**（`zf_old`）时，加一条 factory 即可，不动调用方
- 解析器实现要点（已具备）：**按内容定位，不赌 DOM 下标** ——
  这样页面结构小改不会整体失效

**（3）会话与登录态**

- `SESSION_EXPIRED` 已覆盖"抓到登录页/会话过期页/CAS 跳转页"
- 新增需求：**保留会话上下文**。用户登录到一半失败重试时，不应从头再走一遍学校选择
- 实现：`JwImportActivity` 的 Stage 状态在失败时回退到**上一有效 Stage** 而非起始

**（4）抓取时机**

- `NO_TABLE_CONTAINER` 已覆盖"抓取过早，数据未加载完"
- 重设计后：错误页提供「重试抓取」按钮，且提示"请停在个人课表页"

**（5）学期与空数据**

- `EMPTY_SEMESTER` 已覆盖"页面声明本学期无课"
- 需补：**学期选择引导** —— 提示用户确认教务侧是否已切换到正确学期

**（6）协议不匹配**

- `WRONG_PROTOCOL` 覆盖"iframe 抓取拿不到目标 / 多协议混淆"
- `UNKNOWN_EMPTY` 兜底会回显诊断特征（`matchedFeatures`），便于定位但**不含响应内容** → 保留

### 6.4 兼容性风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 教务系统改版（页面结构变） | 解析失败，导入不可用 | 按内容定位而非 DOM 下标；7 类诊断让用户看到"是页面变了"而非"App 坏了"；文件导入可兜底 |
| 学校加第二所时漏改白名单 | 新学校登不进去 | 白名单下沉数据层 + 契约测试锁定 |
| WebView 内核差异 | JS 桥注入失败 | 已有 `onCaptureError` 回调；需补"换用手动导入"出口 |
| 未登录/跨域 | 拿不到数据 | `SESSION_EXPIRED` + 重新登录入口 |
| **无真机验证条件** | 以上均无法实测 | ⚠️ 见 §8 |

## 8. 风险与前置条件

### 8.1 最大风险：全链路无法实测

本项目**无真机、无模拟器、无 AVD**。这意味着：

- 导航重构（P0）**改的是全 App 的骨架**，但只能靠单测与代码审查验证，无法目视
- 教务导入的所有兼容性改进（P2）**无法真机验证** —— 而它恰恰是用户要求"必须可用"的功能
- 小组件复活（P5）必须在真机上才能确认能否添加

**结论**：P0/P1/P3/P4 可以靠单测 + 契约测试推进；
**P2 与 P5 必须有真机验收**，否则"改完即交付"是自欺。

### 8.2 需要用户拍板的三件事

1. **删除浮动 Dock** —— 这是现有用户已形成肌肉记忆的操作方式，改动感知最强
2. **Tab 语义变更** —— 「管理」并入「设置」，老用户会找不到导入入口（需空态引导补偿）
3. **小组件策略** —— 是"复活 2 种"还是"彻底砍掉"？我倾向复活 2 种（课表 App 的桌面价值高），但这会引入必须真机验证的工作量

### 8.3 不变量（不得违反）

- 教务导入是特色功能，任何阶段不得使其不可用
- WebView 域名白名单严禁扩为通配；证书错误必须 `cancel()`
- 解析失败不得回显响应内容（只回显错误 code 与诊断特征）
- Room 严禁 `fallbackToDestructiveMigration`
- 许可义务：GPL-3.0；第三方来源如实标注
