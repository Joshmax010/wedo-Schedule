## 0.1 这份文档是什么，不是什么

**是**：一套可以直接下达给编码 Agent 的工程蓝图。每个改造对象都有落点文件、状态枚举、材质定额、降级链、验收用例编号。

**不是**：设计理念综述、Apple HIG 翻译、液态玻璃科普。凡是「什么叫玻璃质感」这类问题，本套文档一律假定读者已具备，不重复解释。

**与既有文档的关系**：

| 文档 | 关系 |
|---|---|
| `docs/DESIGN_SPEC_V2.md`（231 行） | **被本套文档取代**（材质与动效章节）。V2 正文不改，仅加取代声明。逐条取代矩阵见 §0.8 |

## 0.4 已锁定决策（写作与实施均不得动摇）

| # | 决策 | 一句话理由 |
|---|---|---|
| **D1** | 玻璃范围 = **全部表面纳入、分级定额**，不是全部最高档 | 「全面玻璃化」若逐字执行，API 26–30 上会退化成满屏半透明色块；分级是唯一自洽解 |
| **D2** | 折射档 = **L0 + L1 + L2 全量**，L2 灰度且默认关 | L2 在滚动路径上不可用（`toImageBitmap()` 是 suspend），只能限静止小面积 |
| **D3** | **minSdk 保持 26**，三档降级 | 抬高 minSdk 是产品决策不是技术决策，不由本次改造单方面决定 |
| **D4** | 文档组织 = **主索引 + 11 卷分册** | 十万字单文件后续 diff 不可读 |
| **D5** | **新写 `DESIGN_SPEC_V4_GLASS.md` 取代 V2** 的材质与动效章节 | V2 是「唯一权威」且明文禁内容层材质，不取代则两套规范互相打脸 |
| **D6** | 三个死开关（减弱动效 / 触觉 / 画质）纳入 **P0 前置** | 没有减动效开关，动效类验收无从谈起；且规范承诺了代码没做 |
| **D7** | 课程块 = **实色底 + G0 镀层**，底色不透明 | 保住 `solveForContrast` 的 6.5:1 推导前提（背景明度恒定） |
| **D8** | BASE 层 = **极低幅中性纹理**，ΔL ≤ 2%，禁品牌色 | 给玻璃可采的内容，同时不重犯 2026-09-27 的「彩色身份」否决 |
| **D9** | 契约测试 **只窄化 1 条**，其余 11 条一字不改 | 动第二条就等于自己拆护栏 |
| **D10** | 真机验收 **不卡阶段门禁、事后补验**，但结论必须显式标注 | 无设备是客观限制，不能靠降低标准掩盖 |

## 0.5 ADR 表（编号从 15 续编，避免与 `ARCH_V3_IMPLEMENTATION.md` 的 ADR-1~8 冲突）

| ADR | 决策 | 主要替代方案 | 否决理由 |
|---|---|---|---|
| **ADR-15** | 语义 / 定额 / 能力拆成**三个独立枚举**（`SurfaceClass` / `QuotaGrade` / `RenderTier`） | 单一 `GlassStyle` 枚举 | 单枚举会产生 `ContentGlass_L1` 这类无意义组合，且无法表达「内容层恒 G0」这条硬规则 |
| **ADR-16** | 复用 `WedoGlassTokens.kt` 的 `buildGlassSpec` 作为**定额内核**，签名从 3 参扩到 5 参 | 新写一套令牌 | 已有 12+ 条单测锁住参数矩阵，推翻等于白扔护栏 |
| **ADR-17** | 不复刻 FlClash 的图集 atlas + 分带 band，改为**单张离屏 + 面板表 SDF** | 照搬图集方案 | 单平台、同屏面板 ≤6，图集收益不抵 1000+ 行复杂度 |
| **ADR-18** | 内容层恒 G0，**永不被配额升档** | 按面积动态升档 | 内容层面积最大、重绘最频繁；升档即性能自杀，且 `Scaffold(containerColor)` 让采样无信息量 |
| **ADR-19** | G0 **独立可交付**：即使 L1/L2 全部失败，G0 仍是净收益 | 全有或全无 | 唯一能对冲「观感被否」风险的结构（见 R-01） |
| **ADR-20** | **不自研弹簧求解器**，用 `Animatable` + 默认速度继承 | 自研 `SpringSimulation` 状态机 | `animateTo` 的 `initialVelocity` 默认就是 `this.velocity`，速度继承与中断续跑是免费的 |
| **ADR-21** | 材质一律画在 `drawBehind` / `drawWithContent`，**不改布局 padding** | 用 `Surface` 包裹 | 改 padding 会撞 `ScheduleHeaderLayoutContractTest:126-135` 的定长窗口断言 |
| **ADR-22** | 契约测试**只窄化 1 条**（`AnimatedVisibility` → `WedoDock`） | 全面改写测试 | 831 个测试是唯一回归网；改写即自毁 |
| **ADR-23** | 新 API 命名 `Modifier.wedoGlassSurface(...)`，**不复用** `wedoGlass` | 复活 `wedoGlass` | `DESIGN_SPEC_V2.md:170` 明文「已删除，勿复活」；复活会造成「需求没变」的误读 |
| **ADR-24** | **不引入 Navigation-Compose**，沿用 `OverlayScreen` 早退链 | 迁移到 NavHost | V3 已论证 push/pop 满足「返回键逐层只退一级」；迁移是纯重构风险 |
| **ADR-25** | **不升级** Compose BOM / AGP / Kotlin | 升级到 1.9 / 2.2 | 1.7.4 已具备 `rememberGraphicsLayer` + `GraphicsLayer.record/drawLayer` + `ShaderBrush`，升版会把 Material3 1.3.0 拖进未知版本 |
| **ADR-26** | 所有 `@RequiresApi(33)` 代码**独立文件** | 同文件内 `SDK_INT` 分支 | `RuntimeShader` 类在 26–32 不存在，同文件引用会在**类校验阶段**失败，不是运行时分支能救的 |
| **ADR-27** | 降级仲裁顺序：**设备能力 > 用户偏好 > 运行时配额** | 用户偏好优先 | 用户选了 Fine 但设备是低内存机，强上 Fine 只会让用户归因「这软件卡」 |
| **ADR-28** | **Bake 优先于 LiveStrip**，默认不用 LiveStrip | 直接上动态采样 | 先证明静态采样正确，再谈动态；顺序反了会同时排查「参数错」和「时序错」两类问题 |
| **ADR-29** | 自动降档**只观测不改用户设置** | 自动改档 | 改用户设置属越权；观测数据先落地，自动一半另行决策（U-01） |

## 0.6 术语锁定表

| 标识 | 中文名 | 英文/代码名 | 含义 | 禁用别名 |
|---|---|---|---|---|
| `SurfaceClass` | 表面等级 | `SurfaceClass` | BASE / CONTENT / FLOAT 三值，语义分类，决定要不要采样 | 层级、层次、layer、tier |
| `QuotaGrade` | 材质定额档 | `QuotaGrade` | G0 / G1 / G2 三值，决定用不用采样、用哪种采样 | 档次、级别、材质等级 |

3. 「待验证」一律写 `VR-xx`（真机验证项）或 `U-nn`（未决事项）。**禁止用「应该没问题」收尾**——那是把不确定性藏进语气里。

## 0.9 决策反转登记（Reversal Register）

**这一节的作用**：任何「之前明确禁止、现在开放」的条款必须在此留名。没有这一节，三个月后必然有人说「这不就是当年被否掉的那个吗」——而且他大概率是对的，只是不知道中间为什么变。

| # | 原条款 | 现条款 | 反转理由 | 必须同时记录的历史 |
|---|---|---|---|---|
| **RR-01** | V2 §1.3 / §2.1：玻璃只属于控件层，内容卡片**禁止**材质、模糊、半透明 | 三层分级定额：CONTENT 恒 G0（镀层，非采样），FLOAT 可 G1/G2 | 「内容卡片禁止材质」的**真实动机**是防止「到处半透明导致可读性崩」，不是禁止一切质感。G0 是镀层，不改变底色不透明度，因此不触发原动机 | **2026-09-27 用户否决**：「全面取消玻璃质感，你做的效果一点都不好看」。当时「27 个测试全绿」。`AppleSystemDiagnostic.kt:10` 已把这条写成常驻教训 |

## 0.15 统计与自检命令

每轮写完后原样执行，把输出贴进 §0.11 与 §0.12。放在这里是为了让任何人（包括未来的 Agent）能复现，而不是依赖「我记得我查过了」。

**字数统计**（中文字符 + 英文词，对齐 Word 中文计数口径）：

```bash
cd docs/glass
for f in *.md; do
  python -c "
import re
s=open(r'$f',encoding='utf-8').read()
cjk=len(re.findall(r'[\u4e00-\u9fff]',s))
en=len(re.findall(r'[A-Za-z][A-Za-z_\.]*',s))
print(f'$f\t{cjk+en}')
"
done
```

**标题禁用别名扫描**（第一轮踩过的坑，单独列一条）：

```bash
grep -n "^#" *.md | grep -E "描边|边框|蒙层|档位|快照|模糊"
```

**ID 定义-引用对账**（以 V-ID 为例，其余族同理）：

```bash
# 每个 V-ID 的出现次数；只在 1 个文件出现 = 未被引用 = C-02/C-03 违规
grep -oh "V-[0-9]\{2\}" *.md | sort | uniq -c | sort -n | head -20
```

**裸数字抽查**（排除表格中带 ID 的行）：

```bash
grep -n "[0-9]" *.md | grep -v "V-\|O-\|M-\|P-\|Q-\|R-\|U-\|L-\|\.kt:\|\.md:\|20[0-9][0-9]" | head -30
```

**判定口径**：`uniq -c` 输出里出现次数为 1 的 ID，必须人工确认「它是不是只在该卷定义处出现一次」——定义处出现 1 次是正常的，但如果它在卷 05 应当被引用却没出现，就是漏引用。

> **PATCH-08（2026-10-26，第 8 轮）**：以上扫描命令会产生**假阳性**，原因是「范围写法」与「空置说明」里的数字会被正则当成真实 ID。实测到三类：
> - `VR-01 … VR-99`（ID 注册表的分配段列）→ 扫出并不存在的 `VR-19`
> - `Q-86`..`Q-99`（说明某段空置）→ 扫出 `Q-86` / `Q-92` / `Q-98` / `Q-99`
> - `V-73 起保留` → 扫出 `V-73` / `V-99`
>
> **修正口径**：扫描前先剔除三类文本——① 含 `…` 或 `..` 的范围表达式；② 「`X-nn` 之后 / 起 / 空置」这类说明；③ `§0.7` 的分配段列。剔除后剩余的单次出现项，才是真正的「定义了但没被引用」。
> 原因分类：**工具缺陷**（不是内容错误）。同时沿用第 1 轮的教训：**保留段与空置段一律用文字描述，不写连字符范围**。

### 18.4 一项「已知偏差」而非缺陷

**检查 4 的结果**：108 个参数 ID（`V` 16 / `O` 40 / `M` 30 / `P` 22）**仅在定义卷出现一次**，未在卷 05 或 06 被引用。

| 判定 | 理由 |
|---|---|
| **可接受** | 参数表天然是「清单」而非「契约」。例如 `O-09`（离屏格式 RGBA8888）是全局前提，不需要每块面板引用它；`M-14`（overshootEasing）只在少数非弹簧场景用 |
| **但含义要说清** | 这些 ID **不是「跨卷契约锚点」**，只是「本卷内的编号条目」。若把它们当成「必须有引用方」的锚点，会误判为 52% 的参数没落地 |
| **规则修订** | `C-02`/`C-03` 应改为：「每个 `O-`/`M-`/`P-ID` 要么被至少一个非定义卷引用，要么属『自足条款』（全局前提或可选替代），后者须在定义卷内标注」 |

→ 记为 `PATCH-11`，性质：**检查规则过严**（与前几轮的规则缺陷同类）。
