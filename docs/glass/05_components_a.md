## 5.1 L-01 · 环境层 `WedoBackground`

### ① 现有功能与调用链

`WedoShell.kt:55-62`。全 app 唯一的不透明底色容器：

```kotlin
fun WedoBackground(modifier: Modifier = Modifier, content: @Composable BoxScope.() -> Unit)
```

调用点：`MainActivity.kt:451`，包住 `CompositionLocalProvider` + `MainTabs` + `WedoTabBar`。底色 `#F2F2F7`（浅）/ `#000000`（深）。

### ② 现存问题

| # | 问题 | 证据 |
|---|---|---|
| 1 | 纯色，无任何层次。玻璃即使做出来也无内容可采（卷 01 §1.1 原因二） | `WedoShell.kt:56-59` |
| 2 | **18 处**不透明底色盖在它上面（10 处 `Scaffold` 默认 `containerColor` + 1 处显式 + 7 处 `.background()`），详见 `L-18` | 见 `L-18` ① 的表 |
| 3 | OLED 纯黑 `#000000` **硬编码两处**（`AppleScheme.kt:56`、`WedoShell.kt:57`），改一处漏一处 | 同左 |

### ③ 预期效果

底色之上叠一层「几乎看不见但有信息」的中性纹理：极淡的径向明度场（中心略亮）+ 确定性噪点。截图上看不出「有一层东西」，但把底栏玻璃盖上去，磨砂区里能看出**不是纯平**。

引用：`V-01`（明度场）、`V-02`（噪点）、`V-03`（深色不提亮）、`V-04`（深色噪点更弱）。

### ④ 9 种状态

本对象无交互，只有 3 种有效状态：

| 状态 | 行为 |
|---|---|
| 浅色 | `V-01` + `V-02` |
| 深色（`#1C1C1E` 系） | `V-01` 减半 + `V-04` |
| 深色（纯黑 OLED） | `V-03`（不提亮，只加中心微高光）+ `V-04` |
| 其余 6 态 | 不适用（无位移、无按压） |
| 减弱动效 | 不适用（本体零动画） |

### ⑤ 材质与动画

| 项 | 值 |
|---|---|
| `SurfaceClass` | `BASE` |
| `QuotaGrade` | 无（BASE 不渲染材质） |
| 降级链 | L0 / L1 / L2 **三者相同**——BASE 永不进 shader（卷 01 §1.3.2 分配表） |
| 弹簧 | 无 |

### ⑥ 需新增能力

| 能力 | 归属 |
|---|---|
| `WedoEnvironmentLayer(modifier)` 可组合 | `ui/glass/`，见卷 06 |
| 确定性噪点 `ImageBitmap` + `BitmapShader(REPEAT)` 的生成与缓存 | `ui/glass/GlassEnvironment.kt` |
| `GLASS_ENABLED` 全局开关 | `ui/glass/GlassCapability.kt` |

### ⑦ 与其他组件关系

- 它是**所有** FLOAT 玻璃的最底层数据源。`L-01` 不成立，`L-02` 的 G2 就采不到东西。
- 它必须包住 `MainTabs` **与** `WedoTabBar`（当前已如此，`MainActivity.kt:451-476`）。
- 它的收益会被 `L-18` 的 18 处底色覆盖抵消 —— **两者必须同批做**，顺序反了等于没做。
- 它**不属于**任何 Host 的 content 槽——Host 在它内部。

### ⑧ 实施顺序依赖

无前置。是 `L-02` / `L-03` / `L-18` 的前置。

### ⑨ 异常与边界

| 边界 | 处理 |
|---|---|
| 极低内存机 | 跳过 `V-02` 噪点，只保留 `V-01` 明度场（省一张 64×64 位图，收益虽小但机制要一致） |
| 纯黑 OLED | 用 `V-03`，**绝不提亮**——OLED 用户对「黑变深灰」极度敏感 |
| `GLASS_ENABLED = false` | 完全退化为今天的 `Box(background(base))`，像素级一致 |
| 屏幕旋转 | 噪点 tile 是 REPEAT 平铺，不随尺寸变，无需重建 |

### ⑩ 验收标准

| Q-ID | 内容 |
|---|---|
| `Q-05` | `GLASS_ENABLED = true` 时，背景存在纹理；取样任意两点，ΔL ≤ 2%（`V-01` 上限） |
| `Q-06` | `GLASS_ENABLED = false` 时，与改造前截图**像素级一致**（0 差异） |
| `Q-53` | 噪点在同分辨率下连续 10 次启动结果一致（确定性，`V-02` 的种子要求） |

## 5.3 L-03 · 课表顶栏 `WedoWeekHeader`

### ① 现有功能与调用链

`WedoWeekHeader.kt`（117 行）。单行结构（`2026-10-02` 真机反馈后重做）：

```
Row(height = minTouchTarget, padding(start = pageMargin, end = 4.dp))
  ├─ Column(weight(1f)).wedoPress { onOpenPicker() }   :76-99
  │    ├─ Text(第 N 周, 20sp SemiBold)                  :82-88

  ├─ WedoIconButton(Add)                                :102
  └─ WedoIconButton(IosShare)                           :104
```

**关键事实：它没有任何背景、没有任何材质。** 直接浮在 `WedoBackground` 上。

### ② 现存问题

| # | 问题 | 证据 |
|---|---|---|
| 1 | 零材质，与底栏（未来是 G2）形成材质断层：一个浮着、一个贴着 | `WedoWeekHeader.kt:68-71` 无 `.background` |
| 2 | 它在 `Column` **正常流**里，内容不上滚到它下面 | `ScheduleScreen.kt:156-166`：`Column { WedoWeekHeader(); Box(weight(1f)) { Pager } }` |
| 3 | `DESIGN_SPEC_V2:158` 承诺「滚动到顶部透明、滚离后变 regular 玻璃」——**该条已被 `RETIRE`**（`V2-21`/`V2-22`），因为它需要滚动量输入，会撞 `B-07` 的 `nestedScroll` 禁令（U-07） | 同左 |

### ③ 预期效果

**结论：顶栏做 G0，不做采样。**

理由链：
1. 问题 2 决定了它**没有内容可采**——下面就是页面背景，采样等于采纯色（违反「不做无效采样」的成本纪律）。
2. 要让它有内容可采，必须改成 overlay 结构（内容滚到它下面），这是**布局改造**，超出材质改造范围，且会改变 `ScheduleScreen` 的滚动语义。
3. 问题 3 已把「滚离变色」判为 `RETIRE`，没有滚动量输入的需求，也就没有做采样的动机。

G0 的视觉效果：顶栏区域有一条极淡的 `V-10` tint + 1dp rim（`V-20`）+ hairline（`V-13`）+ 内高光（`V-14`）。**看起来像一块「薄玻璃片浮在背景上」**，与底栏的「厚玻璃条」形成层次，而不是断层。

引用：`V-10`、`V-12`、`V-13`、`V-14`、`V-20`、`V-24`（L0 双环）。

### ④ 9 种状态

| 状态 | 行为 |
|---|---|
| 静止 | G0；rim + 内高光；文字 `onSurface`（`V-50`） |
| 按下（「第 N 周」整块） | `wedoPress`（`M-02`）→ 打开 `WeekPicker` |
| 按下（＋ / 分享图标） | `wedoPress` + `WedoIconButton` 自身逻辑 |
| 长按 | 不适用 |
| 拖拽中 | 不适用（顶栏不拖） |
| 松手落定 | 不适用 |
| 禁用 | 不适用 |
| 滚动中 | **无变化**（`M-58`：滚动不改组件动画）；材质不降级（本来就是 G0） |
| 减弱动效 | `wedoPress` 走 `snap()`（`M-33`） |

### ⑤ 材质与动画

| 项 | 值 |

## 5.4 L-04 · 分段控件 `SegmentedSwitcher`

### ① 现有功能与调用链

`SegmentedSwitcher.kt`。全仓唯一「手搓物理动画」的组件，也是本次改造**唯一可直接复用的正确范式**（卷 03 §3.1.3）。核心机制：`Animatable` 存逻辑段坐标（`:77`）、`animateTo` 带 `block{}` 逐帧回写（`:80-86`）、`graphicsLayer` 补亚像素余数（`:119-123`）、自定义 `Layout` 在 measure 阶段读值重排（`:166-199`）、字符覆盖率 lerp 上色（`:209-239`）。
